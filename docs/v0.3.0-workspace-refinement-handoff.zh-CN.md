## LG-306 实现细节与验收口径

### 实际行为

- 同一对节点之间只有一条关系时完全维持原样：继续使用 Vue Flow 原生 `smoothstep` 路径与标签中点，外观、标签数量、缩小隐藏阈值（0.6）都不变。
- 同一对无向节点之间存在多条关系时（双向关系，或导入数据里同向/反向的重复关系），按边 id 排序后稳定分配车道：`+1、-1、+2、-2…`。正车道路由到两个节点整体的下方，负车道到上方；标签锚点取车道水平段中点。输入顺序不同不会改变分配结果。
- 分道时先让连线从连接点水平伸出 20px（与 Vue Flow 默认 offset 一致），再绕行；折点用 5px 圆角（与默认 borderRadius 一致）。两节点面对面且之间留有余隙时，两条竖直腿落在间隙内（每侧不超过 gap 的 1/4），横向/纵向错位都不会穿过端点盒；其余互不重叠的排布把竖直腿放到两节点并集外侧。视觉样式（关系色、线宽、透明度、标签底色与内边距、交互宽度）沿用原配置。
- 两节点矩形重叠、或贴边到没有可通行走廊（gap ≤ `EDGE_LANE_MIN_GAP` = 0.5px）时，不存在必然可行的直角避让路径，回退原生 `smoothstep`；此时不承诺“绕开端点”，只保证连线与标签仍可见。
- 选中关系排到 SVG 绘制顺序末尾，标签与描边不会被其他关系压住；其余关系保持原顺序，避免选中态变化时整层重排。
- 变淡关系隐藏标签、缩放到 0.6 以下隐藏全部标签、类型筛选/Focus Mode 隐藏端点等既有规则保持不变。
- 未改节点/关系数据模型、IndexedDB 字段、节点坐标含义、侧栏与 Inspector 布局；没有隐藏、裁剪或改写任何跨类型关系。

### 采用的默认与范围

- `EDGE_LANE_GAP = 36`：标签字号 11px、默认上下内边距 3px，实际标签盒约 18px；36px 是能容纳一行中文标签且留有余量的最小行距。没有新增可配置项。
- 只对“同一对无向节点”分组；不处理不同端点之间恰好落在同一点的一般性标签碰撞，也不处理第三节点对连线的遮挡。
- 只处理左右连接点（当前 `LoreNode` 的唯一连接方式）；非面对面的左右组合（如右↔右）及未来新增的上下连接点都回退到原生 smoothstep。
- 没有定义“全图连线交叉数/标签密度”这类产品指标，也没有为了降低交叉而隐藏关系；不承诺全图无交叉。

### 本次采用的自动化验收（固定 fixture，可复现）

1. 车道分配：双向/四条平行关系按 id 稳定得到 `+1/-1`、`1/-1/2/-2`，与输入顺序无关；不同节点对互不影响。
2. 端点框可路由时不穿节点：端点矩形不重叠、面对面且留有 > 0.5px 走廊时，竖直腿落在间隙内（每侧 ≤ gap/4），在 gap 14、上下错位 (96,128) 这类近距/错位场景下按路径采样断言不穿过两端节点盒；其余互不重叠排布走并集外侧；车道非 0 的折线都不穿过端点盒内部。
3. 退化不保证：两节点重叠或贴边到 gap ≤ 0.5 时回退 `smoothstep`（测试固定该行为），此时不做避让承诺；不处理第三节点遮挡，也不承诺全图无交叉。
4. 标签与路径：上下车道标签锚点相距 `52 + 2×36 = 124px`，标签盒不可能重叠；唯一关系不生成自定义折点、标签仍在路径中点。
5. 绘制顺序：选中关系排到最后；无选中或 id 不存在时保持原顺序。

## LG-308 实现细节与验收口径

### 实际行为

- 「更多」菜单在力导向、层级之后新增第三项「自动布局（按类型）」（`auto-layout-clustered-btn`），与前两项共用 `auto-layout` 事件、`layouting` 禁用态、「已自动布局」提示与 8 秒撤销入口。
- 点击后才计算并写坐标：按 `node.type` 分簇；每簇只用簇内关系做一次 force 布局（复用同一个懒加载 ELK 实例，串行 `await`），再用每簇真实包围盒（节点实际宽高，缺省 210×52）逐行排簇。水平簇间距 240、垂直 200、整体留白 40；大簇按自身宽度占位，不会被固定格子挤进相邻簇。
- 跨类型关系不参与簇内布局，但不删除、不隐藏、不改关系数据；画布仍按「两端节点可见」渲染这些边。
- 没有关系的孤立节点也能成簇；缺失 `type` 的节点归入同一簇；只有一种类型或空图时退化为 force，坐标与 force 完全一致；导入来的、当前世界未定义的类型按原始 key 成簇。
- 写路径完全复用 `applyLayout`：单次批量 `updateNodePositions`、首快照、撤销、拖动/切世界失效、落库失败回滚、`isLayouting` 防重入都不变。
- 只在用户点击时布局：加载世界、切换世界、导入片段、类型筛选、watch 都不会调用 `applyLayout`。

### 采用的默认与范围

- 触发与覆盖策略采用保守默认：**仅菜单点击**，不自动覆盖手动布局；手动拖动仍会丢弃首快照，恢复项随之禁用。
- 簇顺序按 type key 排序，簇内沿用 force 的固定随机种子（`elk.randomSeed=1`）→ 同一份数据每次得到相同坐标。
- 未新增依赖、配置项、IndexedDB 字段、数据模型或新快照；`LayoutNodeInput` 只增加可选 `group`，store 透传 `node.type`。
- 簇内仍是 force，不保证簇内最小交叉；跨簇边是 `smoothstep` 直线，可能从第三簇上方经过（跨簇边路由不在本次范围）。

### 本次采用的自动化验收（固定 fixture，可复现）

1. 分簇几何：三簇（角色 / 地点 / 导入类型）覆盖全部节点、坐标为整数、两两包围盒分离；大簇（8 节点）+ 单节点簇仍不重叠。
2. 跨类型边不影响坐标：带跨类型边与只保留簇内边得到的结果完全相同；单簇 / 无 group 与 force 结果一致；连续两次计算相同。
3. 存储：clustered 只调用一次 `updateNodePositions`，不触发逐节点 autosave；同类型节点聚簇且异类型包围盒不重叠。
4. 浏览器：角色「澜舟」「墨鸦」+ 地点「沉钟湾」、两条跨类型关系；聚集后两簇包围盒分离、关系数不变且两条边仍渲染、刷新后库内坐标与画布渲染一致；菜单「恢复布局前位置」与提示「撤销」都回到布局前坐标。
